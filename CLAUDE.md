# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Smart irrigation controller on an STM32F103C8 (Blue Pill): STM32CubeMX HAL + FreeRTOS (CMSIS-RTOS v1), 5 tasks. Simulated on Renode, with an Arduino sketch for Mokxi/Wokwi. University team project; docs, README and code comments are in Vietnamese (code comments without diacritics).

## Commands

All firmware commands run from `firmware/SmartIrrigation/`:

```bash
make         # build build/Project.elf/.hex/.bin with arm-none-eabi-gcc
make clean
renode --console --disable-gui -e "include @test_irrigation.resc"   # automated tests T1–T13
renode -e "i @irrigation.resc"                                      # interactive sim, GDB server on :3333
```

- Always use `renode -e "include @..."`. Passing the script as an argument fails with `Could not tokenize` because the repo path contains spaces.
- Each test step in `test_irrigation.resc` prints `=== Tn ... expect True|False`, then the relay state (`True` = pump ON). There is no per-test runner. To run one scenario, copy the setup lines plus that block into a new `.resc`, or drive it interactively from the monitor.
- Sim controls: `sysbus WriteDoubleWord 0x400127FC <raw 0..4095>` sets the soil ADC value. Percent = `(raw-3164)*100/(1576-3164)`; raw outside `[WET-300, DRY+300]` makes the sensor read invalid. `sysbus.gpioPortB OnGPIO <5|6|7|8> false/true` presses/releases MODE/UP/DOWN/PUMP (pull-up: `true` = released). `sysbus.usart2 WriteChar 0x6D` sends a UART command. `sysbus.gpioPortA.relay State` reads the pump.

## Build system quirks (Makefile)

- The `Makefile` is hand-maintained and is not generated by CubeMX. New `.c` files must be added to `C_SOURCES` by hand. CubeIDE builds use `.cproject` instead, which picks up everything under `Core/` automatically.
- Leftover from the split-branch era: when `Core/Src/main.c` is missing, `CA_DIR` falls back to a `../../.ca/` snapshot fetched by `make ca`. On `main`, `CA_DIR` is `.`, so `make ca` and `.ca/` are not needed.

## Architecture

- `main.c` (Ca, CubeMX-generated) initializes peripherals, then calls `MX_FREERTOS_Init()` and `osKernelStart()`. All 5 tasks are created in `Core/Src/freertos.c`. Priorities: control `AboveNormal`; button and sensor `Normal`; display and UART `BelowNormal`.
- **Shared state:** a single `system_data_t g_system_data` (soil %, setpoint, mode, pump_on, sensor_valid), guarded by `systemDataMutex`. Display and UART tasks copy a snapshot under the mutex, release it, and only then do slow I/O.
- **Input path:** the button task debounces (3 samples at 20 ms) and increments `g_button_press_count[i]`. The UART RX ISR in `uart_comm.c` maps chars (`m` MODE, `p` PUMP, `+`/`-` UP/DOWN) to the separate `g_uart_press_count[i]`. The control task keeps "handled" counters and replays the difference through `irrigation_control_handle_button()`. So UART commands are virtual button presses, and no queue is involved. Each counter array has a single writer.
- **Control logic** lives in `irrigation_control.c`, and every call there runs with the mutex held. State machine `system_mode_t`: `MODE_AUTO=0, MODE_MANUAL, MODE_IDLE, MODE_ERROR`. New values must be appended, because the LCD/UART string tables index by enum value.
  - Boot enters IDLE, then AUTO on the first valid reading.
  - AUTO goes to ERROR when the sensor reads invalid, and back to AUTO when it recovers.
  - MODE toggles MANUAL ↔ AUTO from any state.
  - `enter_state()` always turns the pump off.
  - AUTO uses ±`HYSTERESIS` (5%) around the setpoint: ON below `SET-5`, OFF at `SET+5` or above, hold in between.
  - Setpoint moves in steps of 5, clamped to 10–90.
- Relay on PA4 is active-low (LOW = pump ON). Pins and periods are in Ca's `app_config.h` and `main.h`. `SOIL_ADC_DRY`/`SOIL_ADC_WET` are simulation values and need calibration on real hardware.
- **CubeMX regeneration:** `osThreadDef(...)` lines (priority, stack) are outside `USER CODE` blocks. Keep `SmartIrrigation.ioc` (`FREERTOS.Tasks01`) in sync, or regenerating will revert them. `displayTask` needs a 384-word stack for `snprintf`.
- **Renode model** (`irrigation.repl`): the stock `stm32f103.repl` cannot boot this HAL code. The repl therefore adds bit-banding, Python stubs for RCC (ready bits and SWS mirroring) and FLASH_ACR, and a hand-written ADC1 whose value is set through the fake register at `0x400127FC`. The relay is modelled as an inverted LED on PA4. The LCD is not simulated, so observe the system through the usart2 log and the relay.
- `simulation/mokxi/sketch.ino` is the Arduino reference implementation of the same logic. It uses a single threshold, with no hysteresis and no IDLE/ERROR states.
